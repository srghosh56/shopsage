# Model card: ShopSage

## Overview

ShopSage recommends products to the B2B customers of a UK online gift-ware wholesaler, segments
those customers and predicts their 12-month value. An LLM only *explains* results the models
produced, and an assistant answers questions by calling the same models as tools.

| Component | Model | Library |
|---|---|---|
| Discovery recommendations | Implicit ALS (256 factors, reg 5.0, alpha 0.25, log-count confidence) | `implicit` 0.7.3 |
| Re-order recommendations | Buy-again: recency-decayed purchase frequency (half-life 180 d) | own code |
| Evidence / similar items | Item-kNN, cosine with shrinkage | own code |
| Segments | RFM (log + standardised) → K-means, k by silhouette | scikit-learn 1.9.1 |
| CLV | BG/NBD + Gamma-Gamma, MAP fit | pymc-marketing 1.3.0 |
| Explanations / assistant | Any OpenAI-compatible LLM from `.env` (developed with local Mistral 7B via Ollama) | openai, LangGraph |
| Product search | BM25 + all-MiniLM-L6-v2 embeddings, reciprocal rank fusion | rank_bm25, sentence-transformers |

## Data

UCI Online Retail II (CC BY 4.0): 1,067,371 invoice lines, 2009-12-01 to 2011-12-09, mostly UK
wholesale customers. After cleaning (rules and row counts in [DECISIONS.md](DECISIONS.md)):
770,338 lines from 5,839 identified customers and 4,611 products. Guest checkouts (no customer
ID) are excluded from all customer-level models.

## Evaluation

- Recommenders: time-based split (train < 2011-09-01, test Sep–Nov 2011, validation = Jun–Aug
  2011 for tuning), warm customers only, k = 10, two protocols (all purchases / new items only),
  bootstrap 95% intervals.
- CLV: calibration up to 2011-06-09, 183-day holdout, compared with a naive rate baseline.
- Explanations: 30 explanations, rule-based check plus two LLM judges, all 30 labelled by one human.
- Assistant: 40 questions (30 in-scope, 10 out-of-scope/tricky) vs the same LLM without tools.

## Intended use

Internal decision support for a wholesaler: what to show a known customer, who to prioritise,
quick data questions. Not for automated pricing, credit or any decision about individuals beyond
marketing outreach.

## Limitations

- **Old, single-shop data (2009–2011).** Results don't transfer to other shops or today's
  behaviour without retraining.
- **Seasonality.** The test window is the Q4 peak. Rankings between baselines changed between
  validation (summer) and test (autumn); CLV under-predicts Q4 revenue because BG/NBD and
  Gamma-Gamma assume steady behaviour. Use CLV for ranking, not budgets.
- **Warm customers only.** New customers get popularity; cold-start quality is not measured.
- **Catalogue drift.** Items first sold in the test window can't be recommended.
- **Implicit feedback.** A purchase is treated as interest; returns are kept separately and not
  used as negatives.
- **LLM quality depends on the model in `.env`.** With a 7B local model, explanations are often
  embellished. The rule check blocks invented products, numbers and taste claims but not every
  unsupported phrasing. LLM judges disagreed strongly with each other and did not match human labels
  beyond chance, so only the human-labelled rate should be quoted. The assistant can pick the wrong tool or misread a result;
  the grounding guard prevents unverified numbers from being shown, at the cost of sometimes
  returning raw tool output instead of a sentence.
- **Privacy.** Customer IDs are pseudonymous in the source data; there are no names, emails or
  addresses, and the assistant refuses such requests.

## Ethical considerations

Recommendations favour already-popular items less than the baselines do, but they still lean
toward best-sellers (popularity-bias percentile about 0.95). Segment names and suggested actions
are marketing heuristics, not judgements about customers.
